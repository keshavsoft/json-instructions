json-instructions

Guard the instruction → resolve the source → apply the template → write the result.
The instruction runner that drives JSON tree transformations declaratively.

The Story

Every instruction goes through the same four steps. Each step is handled by a dedicated function — sourced from this package or an external one.

1
checkInstruction(instruction, functions, spec)
Guard — validate structure and references before doing any work
local · guards/
2
resolvePath(registry, sourcePath)
Read — pull the source value out of the registry
json-transformer-funcs
3
applyTemplate(source, spec[templateKey])
Transform — stamp the source into the named template
json-transformer-funcs-primitive
4
writePath(registry, destinationPath, result)
Write — navigate the target tree and apply the named action
json-write-path
writePath is now external. It moved to json-write-path. This package owns steps 1–3 (guard, resolve, transform) and orchestrates the call to step 4.

Step 1 — Guard

checkInstruction runs two validations in sequence. If either fails, the instruction is skipped entirely — no partial writes ever happen.

checkStructure

Confirms all required fields (func, templateKey, sourcePath, destinationPath) are present on the instruction object.

checkReferences

Confirms that instruction.func is a known function name and instruction.templateKey exists as a key in spec.

const structurePassed = checkStructure(instruction, showLog, returnLog);
if (!structurePassed) return false;
return checkReferences(instruction, functions, spec, showLog, returnLog);

Step 2 — Resolve

Reads the source value out of the registry by following a sourcePath descriptor — the read-side counterpart of writePath.

const source = resolvePath(registry, instruction.sourcePath);

Step 3 — Transform

Stamps the resolved source value into the named template from spec.json. Returns a fully-formed JSON node.

const result = functions[instruction.func](source, localSpec[templateKey]);

Step 4 — Write

The transformed result is handed off to json-write-path. This package owns no write logic — it delegates entirely.

writePath(registry, instruction.destinationPath, result);

See the json-write-path docs for the full action catalogue (set, push, unshift, pushToRows, unshiftToRows, unshiftSerialToRows).

Instruction Format

{
  "narration": "Prepend the serial header cell to the table header row.",
  "destinationPath": {
    "fileName": "base",
    "dataRole": "table-header-row",
    "filePath": ["children"],
    "action": "unshift"
  },
  "sourcePath": {
    "fileName": "data",
    "filePath": ["serial", "header"]
  },
  "templateKey": "buildHeader",
  "func": "applyTemplate"
}
narration
Human-readable description of what this step does — self-documenting build sequences
sourcePath
Descriptor passed to resolvePath — where to read the input value from
templateKey
Key into spec.json — selects which template to apply to the source
func
Name of the transform function to call (applyTemplate by default)
destinationPath
Descriptor passed to writePath — where + how to write the result

API

import runSingleInstructions, { runSingleInstruction } from "json-instructions";

// Run all instructions in sequence
runSingleInstructions(instructions, registry, spec, showLog, returnLog);

// Run a single instruction
