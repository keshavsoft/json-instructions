Instruction detail

Prepend serial header cell

This is the actual unit of work used by the highest source version in the repo. One instruction reads a value, applies a template, and writes the result to a target path.

Instruction object

{
  "narration": "Prepend the serial header cell to the table header row.",
  "destinationPath": {
    "fileName": "base",
    "dataRole": "table-header-row",
    "filePath": ["children"],
    "action": "unshift"
  },
  "sourcePath": {
    "fileName": "data",
    "filePath": ["serial", "header"]
  },
  "templateKey": "headerSerialCell",
  "func": "applyTemplate"
}

Why this structure?

  • It is atomic: one instruction = one transformation.
  • It is declarative: the JSON tells the code what to do.
  • It is registry-driven: source and destination live in named JSON trees.
  • It is reusable: the template is separate from the instruction.

Field breakdown

narration
Human-readable description of the operation. This makes the instruction readable without needing to understand the code.
sourcePath
Where the value comes from in the registry. In this example it reads from data.serial.header.
templateKey
Which named template is applied. Here it uses headerSerialCell, which is defined in the spec.
func
The transform function to call. This repo uses applyTemplate for template stamping.
destinationPath
Where the result is written and how it is inserted: base.table-header-row.children with action unshift.

Execution pattern from the v11 source

const source = resolvePath(registry, instruction.sourcePath);
const result = functions[instruction.func](source, spec[instruction.templateKey]);
writePath(registry, instruction.destinationPath, result);

This is the actual rule used by the highest version in src/v11/singleInstructions.js. The instruction is the unit, and the runner is just a loop that executes those instructions in order.
